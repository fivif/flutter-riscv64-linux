# 踩坑记录

按遇到顺序。每条给：**症状 → 根因 → 修法**。

---

## 坑 1 · `gn gen` 报 `Script returned 127`

```
ERROR at //flutter/third_party/dart/sdk_args.gni:32:16: Script returned non-zero exit code.
Command: //flutter/third_party/cpython3/bin/python3 .../tools/make_version.py
Returned 127.
```

**根因**：`127` 是「命令找不到」。引擎默认用自带的 `cpython3` 执行 gn 脚本，
这个路径通常不存在。

**修法**：
```bash
gn gen out/riscv64-release --script-executable=/usr/bin/python3
```

---

## 坑 2 · `pci/pci.h` 找不到

```
fatal error: 'pci/pci.h' file not found
```

**根因**：`libpci-dev` 把头条装在 `/usr/include/riscv64-linux-gnu/pci/`，
而引擎用 `use_default_linux_sysroot = false`，不去 triplet 目录找。

**修法**：
```bash
ln -sfn /usr/include/riscv64-linux-gnu/pci /usr/include/pci
```

---

## 坑 3 · `LLVMgold.so` 加载失败（release 链接）

```
riscv64-linux-gnu-ld.bfd: /usr/lib/llvm-21/lib/LLVMgold.so:
  error loading plugin: 没有那个文件或目录
```

**根因**：release 带 `-flto`，用 bfd 链接 LLVM bitcode 需要 gold 插件，
Bianbu 的 llvm-21 **不提供** `LLVMgold.so`。

**注意 `use_lld = true` 无效**：
```
WARNING: Build argument has no effect.
use_lld = true
The variable "use_lld" was set as a build argument
but never appeared in a declare_args() block in any buildfile.
```

**修法**：clang wrapper 把带 `-flto` 的链接步骤路由到 `-fuse-ld=lld`
（见 `docs/01` 第 4 节）。非 LTO 链接与编译不受影响。

---

## 坑 4 · `--rtlib` 与 `--unwindlib` 冲突

**根因**：Bianbu clang 默认 `--rtlib=libgcc`，而
`build/config/compiler/BUILD.gn:645` 注入 `--unwindlib=libunwind`。

**修法**：wrapper 在链接时加 `--rtlib=compiler-rt`。

## 坑 5 · `astcenc_*.cpp` 缺失

```
astcenc_averages_and_directions.cpp: No such file or directory
```

**根因**：`third_party/astcenc` 目录是空的，`git clone` 静默产出 0 个文件。

**修法**：
```bash
curl -L https://codeload.github.com/ARM-software/astc-encoder/tar.gz/2319d9c4d4af53a7fc7c52985e264ce6e8a02a9b \
  | tar xz --strip-components=1
# 应有 552 个文件
```

## 坑 6 · 断开 ssh 后 ninja 被杀

**症状**：构建停在半路，`pgrep ninja` 为 0，日志最后一行停在某个数字不动。

**根因**：`nohup ... &` 不足以脱离会话。

**修法**：
```bash
setsid nohup ninja ... > build.log 2>&1 < /dev/null &
```

**验证真的在跑**：`sleep 60 && tail -3 build.log`，数字必须变化。

## 坑 7 · 同一个 out 目录起了两个 ninja

**症状**：构建行为怪异、目标随机失败、进度倒退。

**修法**：启动前先 `pgrep -a ninja`。同一个 `out/` 目录同时只能有一个 ninja。

## 坑 8 · `create_sdk` 目标名带冒号

```
$ ninja create_sdk
ninja: error: unknown target 'create_sdk'
```

**根因**：GN 的 `toolchain:target` 语法。build.ninja 里是：

```
build flutter/third_party/dart$:create_sdk: phony ...
```

`$:` 转义一个字面冒号。

**修法**：
```bash
ninja "flutter/third_party/dart:create_sdk"
```

## 坑 9 · `create_sdk` 撞 `analysis_server`

第一次：
```
PathNotFoundException(path=.../flutter/third_party/dart/sdk/version; Cannot open file)
```

补上 `sdk/version`（内容 `3.15.0-51.0.dev`）后再跑：
```
Bad state: Future already completed
#0  _AsyncCompleter.complete
#1  LegacyAnalysisServer.handleRequest
```

**根因**：第二个是 `analysis_server` 自己在生成快照时崩，与版本无关。

**修法**：**别编它。** `flutter build` 不需要 `analysis_server` / `dart2js` / `dartdevc`。
只编必需子集（`03-build-dart-sdk.sh`），约 1200 步而不是 3700+。

```bash
ninja -k 0 <4 个 bin 目标> <dart-sdk/lib 的 copy 目标>
```

`-k 0` 让单个目标失败不中断其余。

## 坑 10 · `Wrong full snapshot version`

```
Wrong full snapshot version, expected '919077dd58aa24c9911491c7834311ad'
                          found '79a41e9b2f8c9e7c2c2353277718f1b6'
```

**根因**：换了 Dart SDK 之后，`flutter_tools.snapshot` 还是旧 SDK 编的。

**修法**：
```bash
rm -f $FLUTTER_ROOT/bin/cache/flutter_tools.stamp \
      $FLUTTER_ROOT/bin/cache/flutter_tools.snapshot
flutter --version        # 自动重建，约 10 分钟
```

成功标志：
```
Tools • Dart 3.15.0 (build 3.15.0-51.0.dev) • DevTools 2.61.0
```

**另一个相同的坑**：cargokit 之类用 `dart compile kernel` 的工具，
如果 `dart` 和 `dartaotruntime` 版本不同，也会报同样的错。

## 坑 11 · `Invalid SDK hash` + 窗口全黑

```
[ERROR] Dart Error: Can't load Kernel binary: Invalid SDK hash.
[ERROR] Could not prepare isolate.
[ERROR] Could not create root isolate.
```

**症状很迷惑**：进程活着、窗口在、就是黑屏。

**根因**：`kernel_blob.bin` 是多段 dill 顺序拼接，每段 header 有 10 字节 SDK hash，
由 `frontend_server` 写入。`frontend_server` 的版本 ≠ 引擎 VM 的版本。

**修法**（正确）：用同版本 SDK 重建 `frontend_server_aot`：

```bash
ninja frontend_server_aot      # 约 383 步
cp frontend_server_aot.dart.snapshot $FLUTTER_ROOT/bin/cache/dart-sdk/bin/snapshots/
```

**修法**（应急）：手改 kernel 的 hash。**必须改全部，只改第一个无效**：

```python
# 扫全部 magic 90abcdef，每段 header 的 offset+8..+18 换成目标 hash
```

flutter 的 assemble 流水线可能产出上百段拼接 dill（我们的案例是 177 段）。

## 坑 12 · `ERROR: ApiError` / AOT exit 254

```
ERROR: ApiError
ERROR: Dart snapshot generator failed with exit code 254
ERROR: Target aot_snapshot_release failed
```

**根因**：`gen_snapshot` 校验输入 `app.dill` 的 SDK hash，与自己的版本不符。

**坑中坑**：手改 `app.dill` 的 hash **没用** —— `flutter build` 会重跑
`frontend_server` 把它覆盖回去。

**修法**：同上，重建 `frontend_server_aot` 让它天然产出匹配的 hash。
早期我们试过给 `gen_snapshot` 套 shell 包装来"边编译边改 hash"，
那是治标 —— 真正的解法是统一 SDK 版本。

## 坑 13 · `font-subset` / `shader_lib` 缺失

```
IconTreeShakerException: The font-subset utility is missing. Run "flutter doctor".
```
```
error: '#include' : Included file not found. for header name: flutter/runtime_effect.glsl
```

**修法**：
```bash
ninja font-subset        # 73 步，会连 harfbuzz subset 一起编
cp -af out/.../shader_lib $CACHE_DIR/   # 必须与 impellerc 同级！
```

`shader_lib` 的位置是硬编码的：
```dart
// shader_compiler.dart:223
join(impellerc.parent.absolute.path, 'shader_lib')
```

## 坑 14 · `pub get` 仍去下载 404

```
Failed to download .../linux-riscv64/artifacts.zip
Exception: 404
```

**根因**：`flutter pub get` **不认** `--local-engine` 三个参数，
它照样检查 cache stamp。

**修法**：统一 5 个 stamp（见 README「缓存 stamp」）。

## 坑 15 · `flutter --version` 报 `0.0.0-unknown`

```
The current Flutter SDK version is 0.0.0-unknown.
Because xxx requires Flutter SDK version ^3.41.0, version solving failed.
```

**根因**：clone 没有 git tag，flutter 从 `git describe --tags` 取版本。

**修法**：
```bash
cd $FLUTTER_ROOT && git tag -f 3.41.0 && rm -f bin/cache/flutter.version.json
```

## 坑 16 · 测性能时测错了文件

**这个坑值得单独说**，因为它会让你得出完全相反的结论。

Flutter 应用 bundle 里的 `lib/libflutter_linux_gtk.so` 是**独立拷贝**，
通过 `RUNPATH` 加载，**不是** rpath 链到 `out/`。你重新编译了 `out/` 里的引擎，
但忘了 `cp` 进 bundle，测的还是旧引擎。

我们因此一度得出「release 比 debug 慢 12%」的结论。

**自查**：
```bash
ldd bundle/app | grep flutter
readelf -d bundle/app | grep -E 'RPATH|RUNPATH'
sha256sum bundle/lib/libflutter_linux_gtk.so out/xxx/libflutter_linux_gtk.so
```
三个哈希不一致就是在测别的东西。
