# 环境准备

在动手之前把这几件事做掉，否则后面每个坑都要花半天。

```bash
apt install -y \
  ninja-build gn pkg-config python3 \

  libfontconfig1-dev libfreetype6-dev
```

## 2. `libpci` 头文件位置

引擎的 `SystemInfo_libpci.cpp` 用 `#include <pci/pci.h>`，而 Debian/Ubuntu 系把
`libpci-dev` 的头装在 `/usr/include/<triplet>/pci/`。

引擎构建用 `use_default_linux_sysroot = false`，不会去 triplet 目录找。所以要建软链：

```bash
ln -sfn /usr/include/riscv64-linux-gnu/pci /usr/include/pci
```

不做的报错：

```
fatal error: 'pci/pci.h' file not found
```

## 3. `gn` 必须显式指定 python

直接 `gn gen out/xxx` 会失败：

```
ERROR at //flutter/third_party/dart/sdk_args.gni:32:16: Script returned non-zero exit code.
Command: //flutter/third_party/cpython3/bin/python3 .../tools/make_version.py --format={{GIT_HASH}}
Returned 127.
```

`127` = 找不到解释器。引擎默认用 `//flutter/third_party/cpython3/bin/python3`，
这个路径在你的机器上很可能不存在。

**解法：**

```bash
gn gen out/riscv64-release --script-executable=/usr/bin/python3
```

（也可以把 `deps/cpython3` 拷到 `flutter/third_party/cpython3`，但没必要。）

## 4. clang shim（两个必打的补丁）

把 `scripts/wrappers/clang` 和 `clang++` 覆盖到引擎的 buildtools 里：

```bash
ENGINE_SRC=/path/to/engine/src
cp scripts/wrappers/clang scripts/wrappers/clang++ \
   "$ENGINE_SRC/buildtools/linux-x64/clang/bin/"
```

它解决两个问题：

### 4.1 `--rtlib` 冲突（debug / 所有链接）

Bianbu 的 clang 默认 `--rtlib=libgcc`，而 `build/config/compiler/BUILD.gn:645`
在 `use_flutter_cxx` 时注入 `--unwindlib=libunwind`，二者冲突。

wrapper 在**链接**步骤加 `--rtlib=compiler-rt` —— 只在链接时加，不污染编译命令。

### 4.2 `-flto` 需要 lld（release 专用）

`enable_lto=true`（`build/toolchain/clang.gni:12`）让 release 带 `-flto`。
用 bfd 链接 LLVM bitcode 需要 gold 插件：

```
riscv64-linux-gnu-ld.bfd: /usr/lib/llvm-21/lib/LLVMgold.so: error loading plugin: 没有那个文件或目录
```

**Bianbu 的 llvm-21 不带 `LLVMgold.so`。**

注意：在 `args.gn` 里写 `use_lld = true` **没有用** —— GN 会警告：

```
WARNING: Build argument has no effect.
use_lld = true
The variable "use_lld" was set as a build argument
but never appeared in a declare_args() block in any buildfile.
```

所以只能从 wrapper 层把 **LTO 链接步骤** 路由到 `-fuse-ld=lld`。
非 LTO 链接和所有编译步骤保持原样，**debug 构建不受影响**。

wrapper 的判定逻辑：

```bash
for a in "$@"; do case "$a" in
  -c|-E|-S|-M|-MM) exec clang "$@";;        # 编译，原样
esac; done
for a in "$@"; do case "$a" in
  -flto) exec clang "$@" --rtlib=compiler-rt -fuse-ld=lld;;   # LTO 链接
esac; done
exec clang "$@" --rtlib=compiler-rt                            # 普通链接
```

## 5. astcenc 源码可能拉取不全

如果 `third_party/astcenc` 目录为空，构建会报：

```
astcenc_averages_and_directions.cpp: No such file or directory
```

`git clone` 有时会静默产出 0 个文件。用 tarball 兜底：

```bash
cd third_party/astcenc
curl -L https://codeload.github.com/ARM-software/astc-encoder/tar.gz/2319d9c4d4af53a7fc7c52985e264ce6e8a02a9b \
  | tar xz --strip-components=1
ls Source/*.cpp | wc -l     # 应为 552 个文件
```

## 6. 长构建必须 `setsid`

引擎构建要 1.5 小时以上。如果直接 `nohup ninja ... &` 然后断开 ssh，
ninja 会被一起杀掉，构建停在半路。

```bash
setsid nohup ninja ... > build.log 2>&1 < /dev/null &
```

判断是否真的在跑（而不是卡死）：

```bash
sleep 60 && tail -3 build.log && pgrep -c ninja
```

**只启动一次。** 同一个 `out/` 目录起两个 ninja 会互相破坏：

```bash
pgrep -a ninja      # 先看有没有别人在跑
```
